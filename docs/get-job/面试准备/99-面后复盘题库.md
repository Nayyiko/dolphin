## 二、已沉淀题库（先把这些题背熟，面试后再追加）

### 分布式/选主（Dolphin 弹药区）
- 为什么 etcd 选主不用 Redis 锁？ → P1-B2：Lease 过期后旧主写入被拒
- Lease TTL 为什么是 15s？ → 3 倍于续约间隔 + 覆盖调度周期
- 网络分区时选主会怎样？ → CP：短暂无主，非双主
- 至少一次 vs 恰好一次，你实现哪种？ → 至少一次 + 幂等 instance_id

### Go 并发（贴项目）
- WorkQueue 为什么改用 GetCtx？ → sync.Cond 不响应 ctx 取消，Leader 失权不停循环
- 内存逃逸举例？ → Reconcile 返回对象
- context 取消链路？ → onBecomeLeader → WithCancel → leader 循环

### 工程/监控
- 埋了哪些 Prometheus 指标？为什么选这些？ → 调度延迟/选主状态/队列深度/worker 在线数
- 假脑裂怎么排查的？ → STAR（先怀疑观测，读源码确认不可能双主）

### 存储/缓存
- Redis Lua 怎么保证原子性？ → 脚本整体执行
- MySQL 隔离级别？ → RR + 间隙锁（任务/日志表）

### 算法
- 滑动窗口最小值 → 单调队列
- 两队列实现栈 / 栈实现队列
- 手写限流器 → Redis 令牌桶 + Lua（复用项目）

## 四、长期沉淀规则

- **问倒过的题** → 必须写进"已沉淀题库"，附正确答案，下次不空着。
- **面试官主动追的点** → 说明那是他关注的能力信号，反向补充对应 bullet 的深度。
- **每 3 次面试后** → 通读一遍 `00-总览`，检查风险地图和 bullet coverage 是否还有漏洞。
- **拿到具体公司 offer/面试邀请** → 回 Stage 1 绑定该公司 JD 重新对齐，再补该公司轮次文件。
