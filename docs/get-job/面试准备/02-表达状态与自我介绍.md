# 02 · 表达状态与自我介绍

> 目标：面试时稳定、自然、可信地把 Dolphin 讲清楚，不卑不亢。不是背稿，是把逻辑梳理透。

---

## 一、面试姿态（先记住这个）

**不卑不亢，落落大方。** 反面例子两类：

- ❌ 过度谨慎/讨好：满口"不好意思""我不太确定是不是"、不敢说结论。→ 让面试官怀疑你入职后扛不住质疑。
- ❌ 傲慢/敷衍：一句话甩答案、等面试官追、显得不耐烦。→ 让人担心协作成本。

**落地动作**：
- 说结论再说理由："我用了 etcd 选主，原因是……"
- 被追问时不慌：先确认问题（"你问的是选主还是脑裂防护？"），再答。
- 每个王牌项目能用 90 秒讲完；超过 2 分钟停不下来 = 信息筛选不够。

---

## 二、通用自我介绍（30–60 秒）

### 口语版
"您好，我是马心怡，武汉大学在读，主要方向是 Go 后端和分布式系统。我做过一个受 Kubernetes 控制器模式启发的 Go 分布式任务调度平台，核心是 Informer + WorkQueue + Reconcile 的事件驱动调度，调度器高可用用 etcd 选主、从机制上防脑裂，任务侧用幂等 instance_id 保证不丢不重。整个系统我做了 Prometheus 埋点和故障注入测试，实测 Leader 接管 11–15 秒、Worker 恢复 22–29 秒、幂等验证通过。我投这个岗位，是因为它需要把 Go 的并发、一致性、存储这些串起来——我的 Dolphin 项目正好把这几块真实跑通了。如果您对哪段感兴趣，我可以具体展开。"

### 关键字卡（脱稿用，只记 5–7 个词）
`K8s 控制器模式` → `etcd 选主防脑裂` → `幂等不丢不重` → `Prometheus + 故障注入` → `11.2–15.64s / 22.68–29.4s 硬数据`

### 避雷提醒
- 不读屏、不背逐字稿。
- 不道歉式开场（"我可能讲得不好"）。
- 不把项目细节一次性全倒完——留"可展开入口"（最后一句主动给钩子）。
- 不说"我做了很多""很复杂"这种无信息量的话。

## 三、Dolphin 项目逐字稿（90 秒可讲）

**背景**：需要一个分布式定时任务调度平台。不用定时扫库，因为它有 O(N) 扫描 + 时间窗滞后的硬伤。
**我做了什么**：完整设计并实现了三个角色——Gateway（API 面）、Scheduler（控制面）、Worker（执行面），外加 etcd 选主、MySQL 持久化、Redis 限流。
**怎么分步做**：先搭控制器模式骨架（Informer/WorkQueue/Reconcile）→ 加 etcd 选主 + 防脑裂 → 补 Worker 心跳 + 幂等 → 做 Prometheus 埋点 → 写故障注入测试反复验证。
**结果是什么**：硬数据全部实测——Leader 接管 N=10 分布 11.2–15.64s 落理论窗口、Worker 恢复 22.68–29.4s、幂等 5 次 PASS、调度延迟 P50 1.4s。
**困难是什么**：踩过"假脑裂"——测出双主 + 1 秒接管，后来定位是测试脚本用子串匹配命中了 Prometheus HELP 行，不是真脑裂。我因此学会先怀疑观测手段。
**下次怎么优化**：把 Informer 轮询升级成 etcd watch 把调度延迟降到毫秒级；补 Redis 高可用；把故障注入测试 CI 化。

## 四、不会就问的边界句（练熟，防崩）

```
"这个点我没有完整做过，现在不敢给您编一个确定答案。
 我能讲清的是 X；如果要落地，我会先验证 Y，再补 Z。"
```

示例：
- 被问 Redis Cluster：→ "Redis 集群本身我没在生产跑过，我能讲清的是 Dolphin 里 Redis 单点的用法；集群的话我会先验证槽位迁移和 failover 再上线。"
- 被问高级算法题卡住：→ "这题我现在没有稳定解，我先讲思路：……。麻烦您给点提示，我可以接着往下想。"

**核心**：会就是会，不会就是不会，绝不瞎猜硬编。模糊化 = 承认记不清，不是编新谎。

## 五、练习动作（面试前 1–2 天）

1. 录 45–60 秒自我介绍，回放看眼神/语速/停顿，确认不像读稿。
2. 对着 `01` 的每条 bullet，口头讲 30 秒讲法；每条至少讲 2 遍，直到不依赖文档。
3. 模拟被追问：请一个朋友/或自己提问"TTL 为什么是 15 秒？"练边界句。
4. 把数字分布练到脱口而出：**11.2–15.64 / 22.68–29.4 / P50 1.4s / 幂等 5 次 PASS**。
5. 面试前一晚只过 `00-总览` 的"只能记 3 条"，不临时抱佛脚堆八股。
